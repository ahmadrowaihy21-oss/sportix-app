# SPORTIX PARTNERS & ROOMS CONNECT MVP

نسخة مراجعة 0.1 — 9 نوفمبر 2026، بتوقيت السعودية. لا توجد عمليات نشر أو تعديل لمستودعات أو إرسال خارجي. جميع سجلات الشركاء والمنشآت والغرف والحجوزات والمدفوعات اصطناعية.

## ما أنجزته النسخة

- واجهة عربية RTL بهوية فحمية/ليمونية، متجاوبة مع الجوال.
- رحلة تقديم شريك ومراجعة مستقلة، مع تبديل أدوار اصطناعي.
- إدارة 4 موارد اصطناعية: السعر بالساعة والسعة وساعات العمل والتوافر والصيانة والسلامة والأهلية والسياسات. الموارد Seed مستقلة عن ملف الشريك الجديد في شاشة التسجيل.
- مطابقة الغرفة حسب الرياضة والمدينة والموعد والمدة والسعة والحد الأدنى والسياسات، مع أسباب استبعاد صريحة. المسافة الجغرافية الدقيقة ليست منفذة.
- REQUESTED → TEMPORARY_SLOT_HOLD → VENUE_NOTIFIED → CLAIMED (اختياري) → CONFIRMED أو VALID_REJECT؛ مع CANCELLED وEXPIRED.
- قفل حصري في ذاكرة واحدة، إعادة الطلب بمفتاح idempotency، version/lease، تفويض اصطناعي مطابق للمبلغ والعملة والحجز، منع التأكيد عند الصيانة أو حظر السلامة أو التوافر القديم.
- سجل أحداث وتنزيل JSON، حفظ محلي آمن عند توفر localStorage، و10 مهام تنفيذ مقترحة قابلة للمتابعة دون مزامنة خارجية.
- نموذج بيانات من 12 مجموعة كيانات، 17 عقد API مقترحًا مع ملف OpenAPI 3.1، مصفوفة أدوار ومصفوفة إعادة استخدام.
- 28 اختبارًا منفذًا للمحاكاة وسجل منفصل من 8 اختبارات قبول إنتاجية لم تُنفذ.

## حدود مثبتة

المحرك محلي ومتزامن داخل عملية JavaScript واحدة. نتيجة سباق طلبين في الذاكرة لا تثبت معاملات موزعة. لا توجد مصادقة حقيقية أو قاعدة بيانات إنتاج أو دفع أو إشعارات أو مزامنة تقويم. تغيير الدور ليس تسجيل دخول. تبديل السلامة في شاشة الموارد أداة لإعداد سيناريو الاختبار، وليس موافقة سلامة حقيقية.

الساعة الاصطناعية تبدأ في 10 نوفمبر 2026، 18:00 بتوقيت السعودية؛ أزرار الوقت تحركها. الموعد الابتدائي 20:00–21:00. مدة القفل 5 دقائق وحداثة التوافر 60 ثانية اقتراحان غير معتمدين تشغيليًا. العملة SAR والقيم ظاهرة للتوضيح؛ في عقود API تخزن المبالغ بالهللات. الأسعار لا تمثل عرضًا تجاريًا أو سياسة ضريبية نهائية.

اختيار المنشأة أو Claim أو تأكيد حضور الغرفة لا يؤكد الحجز. الحضور لا يكفي لمنح نقاط أو verified رياضي. تفويض الدفع لا يساوي تحصيلًا، وVOID_PENDING / REFUND_PENDING لا يعني نجاح الإلغاء المالي أو الاسترداد.

## تصميم التنفيذ المقترح

### القفل والسباق

المورد المادي هو وحدة التخصيص الحصري؛ سعة اللاعبين ليست مخزون حجوزات مشتركة. عند HOLD أو CONFIRM، تستخدم معاملة خادم قفل صف المورد والحجز مع قيود عدم تداخل للفترات [start,end) وإصدار السجل. المقترح يستخدم PostgreSQL EXCLUDE كخيار هندسي، وليس اعتماد بنية تحتية.

تسوية الأقفال المنتهية داخل المعاملة حسب ساعة قاعدة البيانات، مع عامل انتهاء مستقل. لا تعتمد على مؤقت المتصفح، ولا تستخدم now() في شرط فهرس. يفحص التأكيد lease وصلاحيته وتوافرًا حيًا مؤرخًا وأهلية المورد والسياسات والسعة وعدم الصيانة والسلامة، وتفويض الدفع المطابق. يحوّل تخصيص HOLD إلى CONFIRMED داخل المعاملة نفسها دون فجوة تحرير.

تشارك تحديثات الصيانة قفل المورد نفسه. إذا سبقت الصيانة التأكيد تمنعه؛ إذا وقعت بعد تأكيد ملتزم تنشئ حادثًا وتصعيدًا/بديلًا/إلغاءً وفق السياسة. لا تعيد كتابة التاريخ أو تحذف الحجز.

### الدفع والأحداث

مزود الدفع خارج معاملة قاعدة البيانات؛ تستقبل أحداثه بتوقيع وtimestamp وevent_id لمنع التكرار، مع مطابقة merchant/booking/amount/currency/expiry. لا تخزن SPORTIX بيانات البطاقة. تفويض ناجح وصل بعد انتهاء القفل لا يعيد تنشيطه؛ يسجل VOID_PENDING وتبدأ عملية تعويض.

تحفظ أحداث Outbox وسجل التدقيق مع تغيير الحالة. يعاد إرسال الإشعار بلا تكرار حتى إقرار صحيح أو انتهاء المهلة؛ لا يتجاوز فشل الإشعار بوابة VENUE_NOTIFIED. بعد CONFIRMED يمكن بدء CAPTURE في عامل مستقل؛ فشل التحصيل يغيّر حالة الدفع ويصعّد للتشغيل دون حذف الالتزام بالمورد. سياسة التحصيل والإلغاء والاسترداد تحتاج اعتمادًا قبل التنفيذ. الدفع المقسم مؤجل من V1.

### الصلاحيات

هوية وجلسة موثقة على الخادم. tenant_id ليس مدخلًا موثوقًا من المتصفح. مسؤول PARTNERS يعمل ضمن مهمة مدققة؛ الشريك داخل مؤسسته؛ المدير داخل المنشآت المسندة؛ المراجع قراءة/مراجعة ضمن النطاق ودون اعتماد طلبه. خدمات نظام منفصلة عن أدوار البشر. لا تجاوز للصيانة أو السلامة أو الدفع حتى للمسؤول.

## خطة القبول والنشر

P0: عزل المؤسسات، أهلية الشريك، فصل RoomState/BookingState، مخزون ذري، دفع sandbox، واختبارات صيانة/توافر متزامنة. P1: إشعارات مع Outbox، ربط واجهة الرياضي، واستكمال تجربة التشغيل.

المطلوب للاعتماد التالي: نشر معاينة مستقلة خاصة بالمالك بعد مراجعة هذه النسخة. لا يتضمن ذلك تعديل sportix-app أو المواقع القائمة أو إنشاء مهام Linear أو إرسال Slack أو كتابة Notion/Figma. تلك تغييرات منفصلة تتطلب موافقة محددة.

## اختبارات تم تنفيذها

فحص TypeScript وبناء Vinext، و28 حالة اختبار لمحرك المحاكاة. جرى اختبار واجهة الكمبيوتر: المطابقة، طلب/قفل/إشعار، منع التأكيد قبل التفويض، ثم Claim والتأكيد والإلغاء، وتقديم الشريك ومراجعة مستقلة وتشغيل الاختبارات داخل الواجهة. جرى فحص عرض 390 بكسل والتنقل إلى عقود API دون تمرير أفقي على الصفحة.

هذه الأدلة لا تتضمن اختبار قاعدة فعلية أو JWT أو مزود دفع أو notifications أو نِسَب أداء إنتاجية. سجل الاختبارات الآلي بتاريخ التنفيذ موجود في `public/specs/acceptance-results.json`.
