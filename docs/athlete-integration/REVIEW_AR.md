## ما أثبتته مراجعة الكود الأصلي

1. المسارات الأربعة `/communities` و`/go-sportix` و`/sport-id` و`/marketplace` تحمل مكونات تفاعلية داخل EcosystemFrame؛ ليست بحاجة إلى إعادة بناء.
2. `src/lib/go-sportix/store.ts` ينشئ جلسات محلية ويولّد القياسات بواسطة DEMO_SPEED وwobble، ثم يحوّل outcome المختار محليًا إلى VERIFIED_COMPLETED. لا تحقق GPS أو حساسات أو CV خادمي في هذا المسار.
3. publishAndSync ينشر في المجتمع دون تطبيق audience. ثم يكتب سجلًا يوصف بأنه verified ويحدث Weekly عند نتيجة verified المحلية. `recordVerifiedActivity` يزيد extraActivities وsspBonus؛ إزالة تكرار صف السجل لا تمنع زيادة العدادات عند إعادة الاستدعاء.
4. `VIEWER_ID="yousef"` معرف fixture للمجتمع، بينما بديل المصادقة `dev-user`. لا توجد خدمة mapping موحدة بينهما ولا ربط تلك المتاجر بالجلسة.
5. المتاجر الأربعة Zustand داخل الذاكرة. استمرارية onboarding في sessionStorage لا تعني استمرارية سجلات الرياضي ولا مزامنة بين الأجهزة.
6. متجر الرياضي يعتمد mock.ts؛ checkout يقبل outcome من الواجهة ويستطيع تسجيل paid/activated وإصدار قسيمة وخصم النقاط محليًا. rateOrder يستطيع تغيير paid إلى fulfilled. لا يثبت ذلك نجاح دفع أو تسليم حقيقي.
7. توجد بنية مصادقة داعمة، لكن لا حراسة خادمية ولا APIs بيانات لهذه الرحلات. خصوصية SPORT ID الحالية تعتمد عرض الواجهة، وليست تفويضًا على الخادم.
8. مختبر PARTNERS مستقل: D1 sandbox مع ملكية workspace، أدوار ودفع وساعة محاكاة وexternalDelivery معطل. لا يوجد في main جسر تشغيلي مثبت بينه وبين ATHLETE.

## التغييرات المحددة المقترحة

- إضافة `src/lib/athlete/`: عقود Zod للهوية والأوامر والموافقة، محرك حالات محلي، store، bridge إلى متاجر المجتمع وSPORT ID الحالية، محول عقود الشركاء وfixtures اصطناعية.
- تعديل GO SPORTIX لكتابة نفس activityId والهوية الاصطناعية في المسار الموحد، وربط evidence بالجلسة والمالك، والامتناع عن مسار المكافآت والتوثيق القديم. نجاح الاختبار يسمى SIMULATED_COMPLETED. Cycling يبقى للمراجعة.
- إضافة سجل خاص `integrationRecords` في SPORT ID دون زيادة goRecords المعتمدة أو extraActivities أو SSP. منع استدعاء recordVerifiedActivity المحلي من منح اعتماد.
- إظهار اختيارات موافقة لكل نشاط: أنا فقط افتراضيًا، أصدقاء أو عام باختيار صريح، وموافقة منفصلة للمقاييس. تحديث/سحب المنشور عند تغييرها. لا تنسخ صور النشاط أو الصحة أو الموقع إلى المجتمع.
- إعادة استعمال بطاقة المجتمع الحالية، مع تعريف النتيجة الاصطناعية ورفض props القديمة بعد تغيير consentVersion. تعطيل إعادة النشر والرعاية في بطاقة الإسقاط الجديدة؛ يبقى المجتمع القديم ببياناته التجريبية.
- إضافة `/marketplace-integration` لعرض منتج وقسيمة واشتراك من عقد PARTNERS، وإنشاء intents ذات هوية موحدة. لا يحجز مخزونًا ولا يصدر قسيمة ولا يخصم أو يمنح نقاطًا.
- جعل checkout وredeemCoupon وrateOrder القديمة تفشل بصورة مغلقة، وتصفير رصيد/طلبات/قسائم العرض القديمة في store المقترح. كتالوج العرض الأصلي يبقى؛ نجاح محاكاة لا ينتج paid أو activated أو fulfilled.
- إضافة اختبارات العقد والمحرك والمتاجر الفعلية، وأوامر `test:athlete` و`typecheck:athlete`. لم تتغير تبعيات package-lock أو ملفات workflows أو المصادقة الأصلية أو إعدادات نشر.

## حدود المقترح والأعمال التالية

هذه حزمة محلية لتوحيد العقد وإصلاح مسارات العرض الخطرة وإثبات قواعد الرحلة. ليست تشغيلًا متعدد المستخدمين أو حلًا أمنيًا قائمًا على المتصفح. لا تزامن دائم بين الـstores الثلاثة أو استرجاع بعد crash؛ المحرك المحلي يعيد بناء الإسقاطات داخل snapshot واحد، والbridge ينسخها إلى Zustand للعرض. لا تدّعي تلك الآلية معاملة قاعدة بيانات.

تظل نماذج Community وSPORT ID وWeekly Legends القديمة ببيانات عرض اصطناعية، ووظائف Rooms/المسابقة القديمة خارج نطاق هذه الحزمة. لم تُهاجر إلى الهوية الجديدة، ولا تصلح كمصدر مكافآت تشغيلية. مسار GO الجديد لا يستدعي منحها.

قبل التشغيل: تنفيذ طبقة identity/session والـAPI، قاعدة بيانات بمعاملات وعزل، حماية الأدلة والموافقات، دفتر نقاط خادمي، تكامل كتالوج الشركاء والمخزون، ثم الدفع والقسائم مع webhooks واختبارات تزامن فعلية. يتبعها اختبار متصفح ومطابقة الاعتماديات وحل failures الأساسية ذات الصلة ببوابة الإصدار.

## محتويات الحزمة وطريقة المراجعة

- `proposed.patch`: diff كامل للتغييرات المقترحة فقط على commit المحدد، يتضمن الملفات الجديدة.
- `changed-files/`: الملفات المعدلة والجديدة لتسهيل القراءة، وليس نسخة كاملة من المستودع.
- `docs/`: عقد الهوية، خريطة الشركاء، API المقترح، وهذا التقرير.
- `evidence/`: سجلات الفحوص الفعلية وقيد المتصفح والاعتماديات ونتيجة مقارنة baseline.
- `manifest.json` و`TEST_RESULTS.json`: إصدارات المصدر وبصمات الملفات والنتائج المقروءة آليًا.

لا تضم الحزمة .git أو node_modules أو build output أو أسرارًا أو بيانات مستخدمين. يمكن مراجعتها دون تنفيذ أي أمر. تعليمات تطبيق patch محليًا فقط في README_EN.md. الرفع إلى GitHub والدمج والنشر وGitHub Actions متوقفة حتى موافقة المستخدم الصريحة على الإجراء المحدد.
